# Передача файлов: проверка и измерения

Цель — подтвердить передачу файлов по защищённому туннелю с проверкой целостности и измерить полезную скорость доставки. Гипотеза: при включённом сервисе файлы трёх размеров доставляются без изменения байтов; отключённый сервис отклоняет файловые операции. Изменяемые факторы — включение сервиса и размер файла; режим выбора ретрансляторов остаётся random.

Профили `internal/configs/files-enabled.yaml` и `files-disabled.yaml` задают настройки файлового сервиса. Это фрагменты конфигурации для тестового стенда, а не полные конфигурации узла. `files.enabled` управляет отправкой и приёмом. При отсутствии параметра сервис включён для совместимости. `files.download_dir` задаёт выделенный каталог, по умолчанию `downloads`. Для независимых узлов рекомендуется отдельный каталог на каждый узел.

```powershell
./scripts/run_file_experiment.ps1
```

Команда запускает vet, регрессию и пять независимых передач каждого размера: 1024, 102400 и 1048576 байт. Каждая передача использует свежую сеть из пяти логических узлов с отдельными ключами и хранилищами; каталог получателя временный. Тест проверяет оба конфигурационных профиля, отключение сервиса, повреждение файла, а также корректность блока и дедупликацию. Прямой fallback не используется.

Критерий успеха: все тесты проходят, каждая передача завершается подтверждением, размер, SHA-256 и байты совпадают. Ошибка передачи завершает эксперимент неуспешно. Повреждённый файл не должен появляться на диске. Исходные события Go сохраняются в raw.jsonl, измерения — в transfers.csv, число наблюдений и min/max/median/mean goodput — в summary.csv. Goodput вычисляется как размер исходного файла, делённый на время от начала SendFile до проверки файла получателя; время включает подготовку туннеля, шифрование и ACK. Это измерение первой передачи, а не установившейся сессии.

Файл ограничен 64 МиБ, блок — 48 КиБ; последний блок имеет точный остаточный размер. ACK последнего блока выдаётся после проверки итогового SHA-256 и записи файла. Незавершённые данные находятся в памяти туннеля и удаляются при его очистке по TTL. Возобновление передачи после смены туннеля не поддерживается: отсутствие метаданных у нового туннеля приводит к ошибке. Обнаружение SHA-256 ошибки не означает автоматическую повторную загрузку файла.

Результаты локального стенда не доказывают влияние задержек/потерь реального underlay или превосходство рейтинга над случайным выбором. Такие сравнения требуют отдельного эксперимента с контролируемыми условиями.

## Сохранённый результат

Актуальный каталог — results/files-validation. Все 15 передач прошли проверку размера, SHA-256 и байтов. Исходные события, профили и manifest сохранены в evidence/files-validation.zip; transfers.csv и summary.csv доступны без распаковки. Средний goodput, Б/с: 62672.6264, 5130816.1098, 20334941.5534. Это первая передача с подготовкой туннелей на локальном стенде, без netem. Общая свежая регрессия — results/relay-regression.txt.
