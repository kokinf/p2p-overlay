# Architecture Decision Record (ADR)

## 1. Параметры
- **Проект:** Децентрализованная оверлейная сеть на Kademlia DHT.
- **Параметры:** `N=15` (базовый) и `N=21` (продвинутый), `K_BUCKET_SIZE=3` или `4`, `ALPHA=3`, `R=3`, `MAX_FRAME_PAYLOAD=65536`, `MIN_RELAYS=2`.
- **Топологии:** `star`, `ring`, `tree`, `multi-seed`.

## 2. Подсистемы

- **Transport & Framing (`internal/protocol`)**:
  - TCP-транспорт. Кастомный 24-байтовый заголовок кадра (`version`, `type`, `flags`, `request_id`, `length`), Big-Endian.
  - `StreamDecoder` корректно обрабатывает частичные чтения и склеенные пакеты. `payload_length > MAX_FRAME_PAYLOAD` отклоняется **до** выделения буфера.
  - Кадры с `version != 1` отклоняются в `handleRPC` с `FrameError`; узел остаётся работоспособным .
  - Сериализация: MessagePack (меньше и быстрее JSON). Воспроизводимое сравнение — `TestSerializationComparison → results/serialization.csv`.

- **Identity & Security (`internal/identity`, `internal/rpc`)**:
  - Ed25519. `NodeID = SHA-256(pubkey)`. Ключи сохраняются локально в `NODE_STATE_DIR` (0600).
  - **TLS 1.3 mTLS:** 0-RTT отключён. Из сертификата извлекается публичный ключ, вычисляется `NodeID` и сверяется с ожидаемым (защита от MITM).
  - **Replay-защита:** на прикладном уровне `replayCache` по `request_id` с TTL 2 минуты.
  - **Ограничение параллелизма:** семафор на 64 одновременных handler'а на узел.

- **DHT & Lookup (`internal/dht`)**:
  - XOR-метрика. 256 k-buckets (по одному на каждый бит), ёмкость каждого — `K_BUCKET_SIZE`.
  - Вытеснение по LRU: перед удалением узла отправляется `PING`.
  - Итеративный Lookup: параллельные запросы к `ALPHA=3` ближайшим кандидатам.
  - `LookupResult` содержит `InitialClosest` — снимок таблицы **до** поиска, а также полную `Trace` по итерациям.
  - Обновление RT: при получении `PING`, `FIND_NODE` или `FIND_VALUE` узел извлекает поле `Addr` (реальный адрес отправителя) и обновляет свой k-bucket. Это устраняет проблему эфемерных портов.

- **Records & Storage (`internal/records`)**:
  - **Модель:** `NodeRecord` содержит владельца, публичный ключ, адреса, алиас, `Seq`, TTL и подпись Ed25519.
  - **Каноническое представление:** для подписи данные склеиваются в строго заданном порядке байт.
  - **Валидация:** связь `NodeID ↔ pubkey`, подпись, формат `host:port`, `MaxRecordSize (16 KiB)`.
  - **Репликация:** запись отправляется на `R=3` ближайших узла, успех при кворуме (2 из 3).

- **Tunnels & Application (`internal/tunnel`, `internal/node`)**:
  - **Построение:** `BuildTunnel` выбирает ретрансляторов, собирает полный `Path` и отправляет `TunnelBuild` первому узлу.
  - **E2E-шифрование:** X25519 (ECDH) + HKDF-SHA256 + AES-256-GCM.
  - **Стейт-машина:** `BUILDING` → `ACTIVE`. При сбое отправки — `DEGRADED`.
  - **Восстановление:** при ошибке отправки данных узел удаляет упавший ретранслятор из `RT` и строит новый маршрут.
  - **Прикладной уровень:** `AppMessageRequest` шифруется, получатель проверяет `SeenMsgs` (дедупликация).

- **Infrastructure & Orchestration (`scripts/`, `Dockerfile`)**:
  - Сборка в два этапа (`golang:alpine` -> `alpine`).
  - `gen_compose.ps1` генерирует `docker-compose.yml` на лету, создавая N контейнеров с уникальными томами для `state_dir`.
  - `run_experiment.ps1` управляет жизненным циклом контейнеров и внедряет отказы.
  - `verify_results.py` парсит `metrics-*.json` и доказывает выполнение критериев (невырожденность `<80%`, multi-hop поиски `>= 30`).

## 3. Невырожденность DHT и масштабирование

- В `RoutingTable` нет глобального реестра; всё хранится в 256 k-bucket'ах.
- Скрипт `verify_results.py` суммирует контакты во всех bucket'ах каждого узла. Если `contacts >= N-1`, узел считается вырожденным. Требование: таких узлов должно быть `< 20%`.
- `pilot_advanced.ps1` и `run_experiment.ps1` показывают, что при `N=21, K=4` сеть остается невырожденной (`0/21`), а Kademlia генерирует 300+ многопереходных поисков (итераций `>= 2`).

## 4. Поведение при отказах

- **Отказ хранителя:** `FIND_VALUE` идёт итеративно; при таймауте контакт удаляется из shortlist'а, поиск продолжается. (`TestReplicationAndFailure`).
- **Отказ seed-узла:** соединения рвутся, но таблица маршрутизации уже содержит других участников. `Alive nodes: 20` в логах Docker.
- **Отказ ретранслятора:** при ошибке `TunnelData` узел удаляет ретранслятор из RT и перестраивает туннель (`sendMessageInternal` с `allowRetry`).
